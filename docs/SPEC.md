# HomeTex — 개인 가계부 웹앱 기획서

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.1 (2026-10-01) |
| 레포·앱 이름 | HomeTex |
| 작성 근거 | 기존 엑셀 가계부(2026) 202611·202612 시트 형식 + 사용자 확정 사항 |
| 목적 | 엑셀 가계부를 폐지하고, iPhone과 PC(Chrome)에서 보고 수정할 수 있는 웹앱으로 대체 |
| 사용 패턴 | 1인 사용, 월초 1회 입력·확인 중심 |

---

## 1. 개요

### 1.1 배경과 방향

| 결정 | 이유 |
|---|---|
| 백엔드·DB 없이 프론트엔드만 구성 | 월 1회 사용 패턴에서는 무료 서버·DB의 슬립, 일시 중지, 만료 정책이 운영 부담이 됩니다. 서버가 없으면 이 문제가 사라지고 비용도 0원입니다. |
| 데이터는 브라우저 localStorage에 저장 | 금융 데이터가 외부 서버로 나가지 않으므로 로그인 기능이 필요 없고 유출 위험도 낮습니다. |
| 기기 간 동기화는 JSON 파일 내보내기/가져오기 | 엑셀을 폐지하므로 CSV 열람용은 두지 않습니다. JSON은 앱 데이터 구조를 그대로 담을 수 있습니다. |
| React + Vite + TypeScript, Vercel 배포 | 기존 포켓몬 서비스와 같은 구조라 배포·운영 방식을 새로 익힐 필요가 없습니다. |
| iPhone에서는 PWA(홈 화면 추가)로 사용 | Safari는 7일간 방문하지 않은 사이트의 저장 데이터를 삭제합니다(ITP). 홈 화면 웹앱은 이 정책에서 제외됩니다. |

### 1.2 범위

| 포함 | 제외 |
|---|---|
| 월별 입력·자동 계산 화면 | 서버, DB, 로그인 |
| 비율 목표 대비 실제 비교 | CSV/XLSX 내보내기 |
| 연간 요약(표·차트) | 한국 방문 자금 계산기 |
| JSON 내보내기/가져오기(병합) | 수도세 항목 |
| 백업 알림, PWA | 다중 사용자 |

## 2. 용어 정의

| 용어 | 의미 |
|---|---|
| 대상 월 | 급여가 들어온 달. "2026-11"은 11월에 받는 **10월 근무분** 급여를 다룹니다. |
| 테토리 | 세후 수령액(手取り). 직접 입력하며, 전월 값을 이어받습니다. |
| 유초 카드값 | 페이페이 + 라인. 카드값 전용 유초 계좌에서 빠져나가는 금액입니다. |
| 미츠이 | 메인 카드. 유초 카드값과 **별도 항목**으로 관리합니다. |
| 라쿠텐 | 매월 10000엔(고정)을 충전하고, 라쿠텐 결제 과금(클로드 등)이 여기서 빠지는 잔액입니다. |
| 월과금 | 매월 나가는 고정 과금. 항목마다 결제처(계좌/라쿠텐)를 가집니다. |
| 카드 잔액 | 모든 고정 지출과 저축을 빼고 남는 최종 여유 자금입니다. |

## 3. 항목 정의

### 3.1 입력 방식 분류

| 분류 | 항목 | 새 달 생성 시 동작 |
|---|---|---|
| 매달 직접 입력 | 페이페이, 라인, 미츠이, 총근무시간, 소정근무시간, 메모 | 빈 값(0)으로 시작 |
| 전월 값 이어받기 | 테토리, 세전 기본급, 총지급액(메모성), 월과금 항목, 현금, 저축 이체액 | 전월 값을 복사, 필요할 때만 수정 |
| 설정 고정값 | 라쿠텐 충전액(10000), 비율 목표, 잔업 계산 상수, 저축 권장액 반올림 단위 | 설정 화면에서만 변경 |
| 자동 계산 | 4장의 모든 계산 항목 | 입력이 바뀔 때마다 재계산 |

### 3.2 월 데이터 항목

| 그룹 | 항목 | 타입 | 기본값/예시 | 비고 |
|---|---|---|---|---|
| 카드 | 페이페이 | 정수(엔) | 0 | 유초 카드값 |
| 카드 | 라인 | 정수(엔) | 0 | 유초 카드값 |
| 카드 | 미츠이 | 정수(엔) | 0 | 별도 항목 |
| 급여 | 테토리 | 정수(엔) | 전월 값 | 세후 수령액 |
| 급여 | 세전 기본급 | 정수(엔) | 250000 | 잔업수당 계산 기준 |
| 급여 | 총지급액(세전) | 정수(엔), 선택 | 338220 | 메모성. 계산에 쓰지 않음 |
| 근무 | 총근무시간 | 소수(시간) | 0 | 전월 근무분 |
| 근무 | 소정근무시간 | 소수(시간) | 0 | 달마다 다름(144~176) |
| 지출 | 현금 | 정수(엔) | 20000 | 현금 인출액 |
| 저축 | 저축 이체액 | 정수(엔) | 전월 값 | 한 번 입력해 저축 외·저축 누적 양쪽에 사용 |
| 저축 | 저축 조정 | 목록 `{금액, 메모}` | 없음 | 일회성 입출금(예: −250000 "여행 자금") |
| 월과금 | 항목 목록 | `{이름, 세부금액[], 결제처}` | 아래 3.3 | 세부금액은 합산(예: 610 + 700) |
| 기타 | 메모 | 텍스트 | 빈 값 | 약속, 계획 등 자유 기록 |

### 3.3 월과금 기본 항목 (202611 기준)

| 이름 | 세부금액 | 합계 | 결제처 |
|---|---|---|---|
| 공월 | 610, 700 | 1310 | 계좌 |
| 기행 | 1400, 2480 | 3880 | 계좌 |
| 클로드 | 3719 | 3719 | **라쿠텐** |

결제처를 두는 이유는 다음과 같습니다. 엑셀에서는 라쿠텐에서 결제하는 클로드가 카드 잔액에서 이중으로 빠지는 오류가 있었습니다. 결제처로 구분하면 라쿠텐 결제분은 라쿠텐 잔액에서만 빠지고, 카드 잔액에는 라쿠텐 충전액(10000)만 반영됩니다.

## 4. 계산 규칙

모든 금액은 정수(엔)로 다루고, 비율·수당 계산은 **소수점 이하 버림**(엑셀 `ROUNDDOWN(x, 0)`과 동일)을 적용합니다.

### 4.1 급여 흐름

| No | 항목 | 수식 |
|---|---|---|
| C1 | 유초 카드값 | `페이페이 + 라인` |
| C2 | 카드값외 | `테토리 − 유초 카드값` |
| C3 | 저축 외 | `카드값외 − 저축 이체액` |
| C4 | 월과금 합(전체) | `모든 월과금 항목 합계` |
| C5 | 월과금 계좌분 | `결제처 = 계좌인 항목 합계` |
| C6 | 월과금 라쿠텐분 | `결제처 = 라쿠텐인 항목 합계` |
| C7 | 카드 잔액 | `저축 외 − 라쿠텐 충전액 − 현금 − 월과금 계좌분 − 미츠이` |

C7은 엑셀 수식에서 바뀌는 부분입니다. 엑셀은 `저축 외 − 10000 − 클로드 − 현금 − 월과금 합(클로드 포함) − 미츠이`였으므로, 클로드 금액의 2배만큼 카드 잔액이 적게 나왔습니다.

### 4.2 라쿠텐 잔액

| No | 항목 | 수식 |
|---|---|---|
| R1 | 라쿠텐 잔액 | `전월 라쿠텐 잔액 + 라쿠텐 충전액 − 이번 달 월과금 라쿠텐분` |

첫 달의 전월 잔액은 설정의 초기 라쿠텐 잔액을 사용합니다. 차감 기준은 "이번 달"로 통일했습니다.

### 4.3 저축

| No | 항목 | 수식 |
|---|---|---|
| S1 | 저축 누적 | `전월 저축 누적 + 저축 이체액 + Σ저축 조정` |
| S2 | 저축 증감 | `저축 누적 − 전월 저축 누적` |
| S3 | 저축 권장액 | `내림(테토리 × 저축 비율 ÷ 반올림 단위) × 반올림 단위` |

**저축 이체액과 비율 목표의 연동 방식 (권장안)**

| 방식 | 결과 | 판단 |
|---|---|---|
| 이체액을 비율로 자동 결정 | 테토리나 카드값이 크게 변한 달에 카드 잔액이 음수가 될 수 있고, 의도적으로 덜 저축하는 달을 표현하기 어렵습니다. | 채택하지 않음 |
| **이체액은 전월 값을 이어받고, 옆에 권장액(S3)과 차이를 표시. "권장액 적용" 버튼으로 한 번에 반영** | 목표를 늘 보면서도 최종 결정은 직접 합니다. | **채택** |

- 이체액 적용 후 카드 잔액(C7)이 음수가 되면 경고를 표시합니다.
- 참고: 202611 기준 테토리 225979 × 0.31 = 70053이고, 10000 단위로 내리면 70000입니다. 현재 이체액과 일치합니다.

### 4.4 잔업수당 (참고값)

| No | 항목 | 수식 |
|---|---|---|
| O1 | 잔업시간 | `max(0, 총근무시간 − 소정근무시간 − 고정 잔업 포함 시간)` |
| O2 | 잔업수당 | `내림(세전 기본급 ÷ 잔업 분모 × 잔업 배율 × 잔업시간)` |

테토리를 직접 입력하므로 잔업수당은 **테토리 계산에 쓰지 않는 참고값**입니다. 실제 수령액에 잔업수당이 맞게 반영됐는지 확인하는 용도입니다.

- 예: 잔업 10시간 → `내림(250000 ÷ 160 × 1.25 × 10)` = 19531엔

### 4.5 비율 목표와 실제

| 구분 | 목표 금액 | 실제 금액 |
|---|---|---|
| 고정비 | `내림(테토리 × 고정비 비율)` | `유초 카드값 + 미츠이 + 월과금 계좌분 + 라쿠텐 충전액` |
| 지출 | `내림(테토리 × 지출 비율)` | `현금 + 카드 잔액` |
| 저축 | `내림(테토리 × 저축 비율)` | `저축 이체액` |

- 실제 3개 항목의 합은 항상 테토리와 같습니다. 이 성질을 단위 테스트의 불변 조건으로 사용합니다.
- 화면에는 금액, 비율(%), 목표와의 차이를 함께 표시합니다.
- 분류 기준은 엑셀 202605 시트의 "현실" 행을 따랐습니다(카드 청구액을 고정비로 분류).

## 5. 화면 설계

### 5.1 화면 목록

| 경로 | 화면 | 주요 기능 |
|---|---|---|
| `/setup` | 초기 설정 | 데이터가 없을 때만 표시 (9.1 참고) |
| `/` | 홈 | 최신 월로 이동, 백업 상태 표시 |
| `/month/:ym` | 월별 화면 | 입력, 자동 계산, 이전/다음 달 이동 |
| `/summary/:year` | 연간 요약 | 월별 표, 연간 합계, 차트 |
| `/settings` | 설정 | 3.4의 설정 항목 |
| `/backup` | 백업 | JSON 내보내기, 가져오기(미리보기·병합) |

### 5.2 월별 화면 구성 (모바일 우선, 위에서 아래 순서)

1. **헤더**: `◀ 2026-11 (10월분) ▶`. 아직 없는 달로 이동하면 "전월 값으로 새 달 만들기" 버튼을 표시합니다.
2. **이번 달 입력**: 페이페이, 라인, 미츠이, 총근무시간, 소정근무시간
3. **급여 흐름 (계산 결과)**: 테토리 → 카드값외 → 저축 외 → 카드 잔액을 단계별 카드로 표시합니다. 각 단계에서 빠진 항목을 함께 보여줍니다.
4. **저축**: 이체액 입력, 권장액과 차이, "권장액 적용" 버튼, 저축 조정 목록, 저축 누적과 증감
5. **비율 목표 vs 실제**: 3개 항목을 막대로 비교합니다.
6. **이어받은 값 (접힘)**: 테토리, 세전 기본급, 총지급액, 현금, 월과금 항목 편집
7. **라쿠텐**: 잔액과 이번 달 차감 내역
8. **잔업수당 (참고)**: 잔업시간과 예상 수당
9. **메모**

## 6. 데이터 저장과 동기화

### 6.1 저장 구조

localStorage 키 `hometex:v1`에 아래 JSON 전체를 저장합니다. 내보내기 파일도 같은 구조입니다.

```json

### 6.2 내보내기

- 파일명: `hometex-YYYYMMDD-HHmm.json`
- iPhone에서는 Web Share API로 "파일에 저장"이나 iCloud Drive를 고를 수 있게 하고, 지원되지 않으면 다운로드로 대체합니다.
- 내보내기에 성공하면 `meta.lastExportedAt`을 갱신합니다.

### 6.3 가져오기

1. 파일을 선택합니다.
2. `schemaVersion`과 필수 필드를 검증합니다. 실패하면 중단하고 사유를 표시합니다.
3. 현재 데이터와 비교한 미리보기를 보여줍니다(월별 "새 항목 / 가져올 쪽이 최신 / 현재가 최신 / 동일").
4. 사용자가 방식을 선택합니다.
   - **병합(기본)**: 월마다, 그리고 설정마다 `updatedAt`이 더 최신인 쪽을 채택합니다.
   - **전체 덮어쓰기**: 확인 대화상자를 한 번 더 거칩니다.
5. 적용 직전에 현재 데이터를 `hometex:v1:before-import`에 1세대 보관해, 되돌리기를 1회 지원합니다.

### 6.4 백업 알림

## 7. 기술 구성

| 배포 | Vercel (Hobby, 정적 배포) | GitHub push 시 자동 배포 |

### 7.1 디렉터리 구조 (안)

```

## 9. 확정 사항

| No | 내용 | 결정 |
|---|---|---|
| D1 | 과거 데이터 이관 | **이관하지 않음.** 웹앱 구축 후 사용자가 직접 입력합니다. 엑셀 변환 스크립트는 만들지 않습니다. |
| D2 | 비율 "실제"의 고정비 분류 | 유초 카드값(페이페이 + 라인) + 미츠이 + 월과금 계좌분 + 라쿠텐 충전액 |
| D3 | 레포 이름 / 앱 표시 이름 | **HomeTex** / **HomeTex** (PWA manifest의 `name`, `short_name` 동일) |

### 9.1 최초 실행 흐름 (D1에 따른 추가)

과거 데이터가 없으므로, 저장 데이터가 비어 있으면 홈 대신 **초기 설정 화면**(`/setup`)을 표시합니다.

| 입력 | 기본값 | 용도 |
|---|---|---|
| 시작 월 | 현재 월 | 첫 월 데이터 생성 |
| 초기 저축 잔액 | 0 | 첫 달 저축 누적 계산(S1)의 전월 값 |
| 초기 라쿠텐 잔액 | 0 | 첫 달 라쿠텐 잔액 계산(R1)의 전월 값 |
| 월과금 항목 | 3.3의 기본 항목 | 첫 달에 미리 채움, 수정 가능 |
| 테토리, 현금, 저축 이체액 | 빈 값 / 20000 / 빈 값 | 첫 달 입력값 |

- 설정 완료 후 시작 월의 월별 화면으로 이동합니다.
- 초기 설정 화면에는 "백업 파일에서 복원" 버튼도 두어, 두 번째 기기(예: iPhone)는 PC에서 내보낸 JSON으로 바로 시작할 수 있게 합니다.
