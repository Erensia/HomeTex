## 1. 목적

1.0.0에서 기능은 갖춰졌으므로, 1.0.1은 **월초 1회 입력·확인**이라는 사용 패턴에 맞게 화면을 다듬는 데 집중합니다.

- 가장 중요한 결과(카드 잔액)를 가장 먼저 보이게 한다.
- iPhone PWA에서 한 손으로 쉽게 이동하고 입력하게 한다.
- 가독성·터치 영역·접근성 기준을 맞춘다.

## 2. 범위

### 2.1 포함

| 구분 | 내용 |
|---|---|
| 내비게이션 | 숨은 사이드바를 **하단 탭바**로 교체 |
| 홈 | 카드 잔액 강조, 이번 달 입력 상태 표시 |
| 월별 화면 | 입력과 결과 구분, 핵심 요약 상단 배치, 드문 섹션 접기 |
| 입력 UX | 삭제 확인, 금액 입력 안내(`1200+500` 형식), 모바일 줄 구성 정리 |
| 요약 화면 | 21열 표의 모바일 대응(핵심 열 우선, 나머지 펼치기) |
| 비주얼 | 글래스 효과 축소, 대비 개선, 터치 영역 44px, 숫자 정렬, 이모지 → SVG 아이콘 |
| 접근성 | 대비(WCAG AA), 포커스 표시, `prefers-reduced-motion`, 음수의 색 외 표시 |

### 2.2 제외

| 항목 | 이유 |
|---|---|
| **다크 모드** | 이번 범위에서 제외 확정 |
| 계산 로직(`src/domain/`) 변경 | 숫자 결과가 바뀌면 안 됨. 기존 테스트가 그대로 통과해야 함 |
| 저장 구조(`src/storage/`) 변경 | 백업 JSON 호환 유지 |
| 새 기능·새 항목 | 1.0.1은 UI/UX 한정 |
| 새 라이브러리 추가 | 기본적으로 CSS와 기존 의존성으로 해결. 필요 시 사유를 문서에 남김 |

## 4. 설계 방향

### 4.1 하단 탭바 (A1)
- 탭: 홈 / 월별 / 요약 / 설정 / 백업 (기존 5개 유지).
- `env(safe-area-inset-bottom)` 반영, 본문 하단 여백을 탭바 높이만큼 확보.
- 현재 위치 강조, 백업 필요 시 기존 배지(`needBackup`)를 탭 아이콘에 표시.
- 사이드바·로고 토글·`scrim`·`status-bar` 관련 코드와 CSS 제거(죽은 코드 남기지 않음). iOS 상단 상태바 처리가 필요한 부분은 유지 여부를 확인 후 결정.

### 4.2 홈 (A2)
- 카드 잔액을 가장 크게 표시(음수는 부호와 문구로도 표시).
- 저축·라쿠텐·NISA는 보조 지표로 축소.
- 최신 월이 비었는지(입력 필요) 한눈에 알 수 있는 상태 문구.

### 4.3 월별 화면 (A3–A6)
- 상단에 카드 잔액 등 핵심 요약을 배치(스크롤 시 고정하지 않음: 모바일 화면 점유가 큼).
- 섹션을 "입력"과 "결과(읽기 전용)"로 구분.
- 라쿠텐·잔업수당·이어받은 값 등 드문 섹션은 `<details>`로 접기(기존 패턴 재사용).
- 삭제는 `confirm()`으로 확인(별도 모달 컴포넌트는 만들지 않음). 이름·금액이 비어 있는 방금 추가한 행은 확인 없이 삭제.
- 합산 입력 칸에 형식 안내 문구 추가.
- 항목 행은 모바일에서 2단 구성(항목명·금액 / 결제처·합계·삭제)으로 고정.

### 4.4 요약 (A7)
- 표는 핵심 열(월, 테토리, 카드 잔액, 저축 누적)만 기본 표시하고 나머지는 "전체 항목 보기"로 펼치기.
- 첫 열(월) 고정(`position: sticky`)으로 가로 스크롤 시 맥락 유지.

### 4.5 비주얼·접근성 (A8–A12)
- 유리 효과는 `.card`와 탭바에만 유지, input·button은 단색 반투명 흰색으로 변경.
- 보조 텍스트 색 대비를 AA(4.5:1) 이상으로 조정.
- 버튼·탭·입력 최소 높이 44px.
- 금액에 `font-variant-numeric: tabular-nums`.
- 이모지 아이콘은 인라인 SVG로 교체(아이콘 라이브러리는 추가하지 않음).
- `@media (prefers-reduced-motion: reduce)`에서 전환 제거.

## 5. 브랜치·릴리스 절차

```
main ──●────────────────────────────●── (릴리스: dev → main)
        \                          /
        dev ──●──●──●──●──●──●────      (구현·검증)
```

| 단계 | 내용 |
|---|---|
| 1 | `main` 기준으로 `dev` 브랜치 생성 (완료) |
| 2 | `dev`에서 문서 작성 → 구현. 작업 단위마다 커밋하고 `origin/dev`로 push |
| 3 | `dev`에서 `npm test`와 `npm run build` 통과 확인 |
| 4 | 5장 완료 기준을 모두 확인한 뒤 `dev`를 최종 확정 |
| 5 | `dev` → `main` 릴리스 (사용자 승인 후). `package.json` 버전을 `1.0.1`로 올림 |

- `main`에는 직접 커밋하지 않습니다.
- 릴리스(main 병합)는 사용자가 "릴리스" 지시를 한 뒤에만 진행합니다.

## 7. 완료 기준

1. `npm test`, `npm run build`가 통과한다.
2. 계산 결과·저장 데이터 형식이 1.0.0과 동일하다.
3. 모든 터치 대상이 44px 이상이고 본문·보조 텍스트가 대비 AA를 만족한다.
4. 모든 화면이 375px 폭에서 가로 스크롤 없이 사용 가능하다(요약 표의 표 내부 스크롤 제외).
5. 삭제 동작에 확인 단계가 있다.
6. 3장 감사 항목(A1–A12)이 모두 처리되었거나, 보류 사유가 문서에 기록되어 있다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| iOS PWA에서 하단 탭바와 홈 인디케이터 영역이 겹침 | `safe-area-inset-bottom` 적용, 실기기(iPhone) 확인 |
| 상단 `status-bar` 처리 제거 시 iOS 26/27 PWA 상단 블러 회귀 | 기존 주석(`style.css`)의 조건을 확인한 후에만 제거 |
| 월별 화면 재구성 중 입력 상태(`defaultValue`/`onBlur`)가 깨짐 | 금액 합산 입력의 기존 동작을 그대로 두고 레이아웃만 변경 |
| 디자인 변경으로 인한 의도치 않은 로직 변경 | `domain/`·`storage/`는 수정하지 않는다는 원칙 유지 |
